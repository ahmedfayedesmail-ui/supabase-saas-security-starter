# Domain / Brand Decision

## Decision
Do **not** register `saasverify.dev` for this project.

A current web review found an active `SaasVerified / SaaS Verify` service at `saasverify.com` focused on SaaS verification and trust. Using the same core name on `.dev` would create unnecessary brand confusion even if the `.dev` domain itself were technically available.

## Current naming direction
Prefer a short developer-oriented name that describes the product's differentiator without copying an existing active SaaS brand.

Current candidate for registrar verification: **`rlsverify.dev`**.

Rationale:
- Closely matches the product's security-verification concept.
- Uses `.dev`, which is explicitly positioned for developers and technology.
- Avoids the active `SaaS Verify` brand identified during review.
- The name can remain useful even if the product later expands beyond one framework while staying focused on RLS / access verification.

## Verification rule

Do not treat search-engine absence as proof of domain availability. Before purchase, verify the exact domain at an authoritative registrar / registry lookup and confirm the registration and renewal price.

The current environment could not complete a direct authoritative RDAP lookup for each candidate, so availability remains **unverified** until the registrar check is performed by the owner.

## Alternatives

Keep `tenantverify.dev` and `rlsproof.dev` as secondary candidates only if `rlsverify.dev` is unavailable.

Do not use `shipsaas.dev` because a current public site is already operating at that domain. Do not use `saaskit.dev` without a separate brand/conflict review.

## TLD note

`.dev` is appropriate for this product category, but HTTPS is required because the `.dev` TLD is on the HSTS preload list.
